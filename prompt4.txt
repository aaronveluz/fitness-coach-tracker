Create an enterprise-grade, multipurpose, reusable, scalable, and secure full-stack application boilerplate using:

Frontend:
- ReactJS
- TypeScript
- Vite
- React Router
- React Query / TanStack Query
- Zustand or Redux Toolkit for global state management
- React Hook Form
- Zod validation
- Component-based architecture

Backend:
- Node.js
- Express.js
- TypeScript
- REST API architecture
- Sequelize ORM
- MariaDB database
- JWT authentication
- Refresh token system

Database:
- MariaDB
- Migration support
- Seed data support
- Proper indexing strategy
- Transaction support


OBJECTIVE:

Create a reusable enterprise application foundation that can support multiple business systems:

- POS
- Inventory
- ERP
- Accounting
- CRM
- HR systems
- Reporting dashboards
- Integration platforms

The boilerplate must make it easy to add:
- New business modules
- New pages
- New API endpoints
- New database tables
- New reports
- New dashboards
- New integrations

Do not build a single application. Build a reusable framework/platform.

==================================
FRONTEND ARCHITECTURE
==================================

Use feature-based architecture.

Structure:

frontend/src/

app/
 ├── router/
 ├── providers/
 └── store/

features/

 ├── auth/
 ├── users/
 ├── dashboard/
 ├── reports/
 └── sample-module/


Each feature must follow:

feature-name/

pages/
components/
hooks/
services/
api/
types/
schemas/
utils/


Rules:

- Pages should only handle UI composition
- Business logic belongs in hooks/services
- API calls must use centralized API service
- Components must be reusable
- Avoid duplicated code
- Use TypeScript interfaces everywhere
- Support lazy loading
- Support route protection
- Support permission-based menu rendering


Create reusable components:

- DataTable
- Pagination
- Search filters
- Date filters
- Modal dialogs
- Forms
- Dropdowns
- File upload
- Export buttons
- Dashboard widgets


==================================

backend/src/

config/

database/

modules/

 ├── auth/
 ├── users/

 ├── permissions/
 ├── reports/

Rules:

- Handles HTTP only

Service:
- Contains business logic

Repository:
- Handles database operations

Model:
- Sequelize models only

==================================
IMPLEMENTATION PLAN
==================================

Do not generate the entire system immediately.

Build in phases:

Phase 1:
Architecture, folder structure, configuration, documentation.

Phase 2:
Authentication, users, roles, permissions.

Phase 3:
Reusable CRUD engine.

Phase 4:
Reporting framework.

Phase 5:
Sample business module.

Phase 6:
Testing, optimization, security review.


Before coding each phase:
Explain the design decisions and wait for approval.

The final output should be a production-ready enterprise boilerplate that can be reused for many applications with minimal restructuring.
